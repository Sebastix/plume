# Feather design philosophy

October 10, 2026

Feather is a native Android reader for Nostr. It should feel immediate, quiet, and beautiful: a clean page, a soft blue feather, and room for people’s words. Its small feature set is the foundation of its speed and identity.

## Convention over configuration

Feather should work as soon as it opens. Choose sensible shared defaults and use the conventions already attached to a Nostr identity. Every new preference is a cost in attention, interface complexity, and maintenance. Prefer automatic behavior; add a setting only when a meaningful device or accessibility constraint requires it. No setup wizard, relay editor, or technical dashboard belongs in the reading experience.

Connecting a signer supplies identity; its public relay list and follows supply the reading context. Relay discovery, fallback, and connection recovery happen quietly. People should never need to know a relay address to use Feather. The media cache budget is a deliberate exception: device storage is finite, so keep that one useful control, with a sensible 1 GB default.

Account and settings use standard theme-aware bottom sheets, generous spacing, a pale blue accent, and familiar accessible icons. Keep account access on the right of the toolbar. The main toolbar stays outside the horizontal feed pager, with a compact centered selector showing the current category and two neighboring icons on each side, with progressively lower opacity toward the edges. Drive selector icon positions, size, and opacity directly from pager progress so dragging and settling stay in sync. Neighbor icons switch pages on tap; clamp the icon window at the ends so Search is the leftmost slot and no empty slots appear; selection moves within the pill near boundaries. Use the same icon vocabulary as profile tabs, without visible labels or a tab underline. Preserve the shared toolbar’s visibility across horizontal swipes and retain vertical hide/show behavior. The main toolbar floats transparently above scrolling feed content; only the five-icon selector has a rounded pill with a semi-transparent theme surface, with theme-aware circular backgrounds behind the feather and account control; keep the first note below it when the feed is at the top. Open the signed-in profile from that avatar. Show the feather logo only on the main feed; omit it whenever a back button is present. Profile views place settings at the top-right and back navigation at the top-left; logout sits at the top of the settings sheet beside the connected identity, accessible without scrolling through a biography. Guests find settings alongside signer login in the account sheet. The account sheet presents identity and only the relevant actions; the profile follows ants-android’s layout with Feather styling: an optional banner extending behind a transparent toolbar, avatar beside name and username, a left-aligned biography, and compact icon actions. Use theme-aware circular surfaces behind toolbar icons over a banner, and restore the solid toolbar as the banner scrolls away. Keep its surface uncluttered, its spacing generous, and its dividers quiet. Keep biographies compact by default: show at most three lines with an icon-only, accessible expand/collapse chevron when content is hidden. Expanded biographies use the same rich links and Nostr previews as posts, with up to three event cards in place and background reference discovery. Public keys are available through a copy action without occupying the page. Avoid raw protocol values and redundant controls.

## Reading comes first

The main experience is a chronological feed of original notes and NIP-18 text-note reposts. A repost uses a small repost icon and the reposter’s name above the original note, never a visible “reposted by” label. Order it by the repost event’s time; keep the original author, content, media, engagement, and thread actions. Validate enclosed originals independently in the background and fall back to relay discovery when absent. Hide the top bar after 32 dp of downward scrolling and restore it after 32 dp upward; ignore tiny direction changes and restore it at the top. Tap a note’s body or surrounding row to read its conversation. Hand the already-rendered event directly to the detail view and retain it separately from the feed snapshot; never replace a known note with an empty/loading screen while fetching replies. Tap a hashtag to open its chronological feed inside Feather, without introducing a search field. Preserve independent tap actions for links, media, quote previews, and controls; tap its author to read their profile. Preserve the reader’s position when they leave and return. Show cached content promptly, then reconcile relay updates without interrupting reading.

Feather does not create accounts, import keys, edit follows, or support DMs. There are no recommendations or analytics. Tapping a post’s heart sends 🧡 through the connected Android signer; long-press offers six recent/frequent emoji choices plus a full-picker icon. Tapping the displayed reaction again removes it with a signed kind-5 deletion request; selected picker emojis toggle off the same way. Existing public activity is readable: profile tabs separate posts, replies, reactions, and highlights; posts display discovered reply and reaction counts and total validated zap amounts in sats. Counts must not delay rendering. Fetch provider metadata and validate zap receipts on a bounded background worker, then update counts. Never imply an exhaustive network-wide total. Feature proposals must justify the attention, network traffic, memory, and maintenance they add.

Profile tabs use accessible icons without text labels and appear only for discovered public activity. Hide empty categories, including Highlights; probe each supported kind independently in the background so busy note feeds cannot crowd out rarer content. Keep discovered tabs stable while viewing a profile, and make swipes skip hidden tabs. Tap tabs or swipe horizontally between adjacent tabs, without wrapping at the ends. Require a deliberate horizontal gesture so vertical scrolling and refresh keep their behavior. Switching tabs preserves the current list position and toolbar visibility. Neither tapping nor swiping a tab should force a jump to the header or tab bar. Highlights follow ants-android’s reading treatment: surrounding context, warm yellow emphasis on the selected passage, an optional comment above a quiet divider, and linked source/author attribution. Markdown formatting and passage matching run off the UI thread. Detail views show full text and media; feed previews stay compact.

## Content supplies the words

Use familiar icons instead of visible labels wherever an icon can express the action. Load older notes automatically within six items of the list end, using a quiet footer progress indicator and no load-more control. Keep one history request active, read cached pages first, retain visible anchors in bounded windows, and avoid repeatedly requesting an unchanged boundary. Pull-to-refresh returns to the latest notes. Refresh by pulling down on the reading list; expose the same action to screen readers without a visible button. Navigation, account access, settings, expansion, conversation, sharing, and confirmation should not introduce interface prose. Avoid screen titles, empty-state slogans, onboarding copy, and explanatory paragraphs inside the app.

The text people came to read remains: notes, names, biographies, timestamps, public keys, and link destinations. Media storage amounts are values, not labels. A concise error may explain a failure when an icon cannot tell someone how to recover. Android’s signer chooser and system dialogs retain their platform UI.

Every actionable icon needs an accurate accessibility description and a touch target of at least 48 dp. Support TalkBack, large text, and Android navigation. Never make color the only way to identify an action or state. If a feature cannot be understood with familiar controls, simplify its interaction before adding it.

## Lightness is visible

Use the Soft Plume feather, white backgrounds, pale blue surfaces, sky-blue accents, and dark readable text in light mode. Follow Android’s system dark-mode setting automatically: deep blue-charcoal surfaces, soft light text, and the same feather-blue accents. No theme configuration. Use semantic theme colors for controls, links, placeholders, dividers, sheets, and launch surfaces. Keep the decorative blue gentle; use the darker action blue where contrast matters. Favor space, alignment, and typography over borders, cards, shadows, and decoration.

Use Android typography and standard Material components. Set comfortable line spacing for notes, keep author details secondary, and separate entries with restrained dividers. Avoid remote fonts and heavy animations. A feed should feel like reading a page rather than operating a dashboard.

## References belong in the conversation

Render Nostr profile mentions as tappable names and quoted text notes as quiet pale-blue previews. Keep ordinary text selectable. Use Quartz to decode NIP-19 identifiers, follow relay hints within the shared connection budget, and verify fetched events before display. Display cached content first. Preview at most three quotes per note and one nesting level; deeper references stay links. Unsupported event kinds open externally. Missing notes retain an unobtrusive reference that can be opened.

Resolve metadata for visible notes and a few upcoming items, including quote authors and profile mentions. Bound requests to 160 profile identities and 24 quoted notes at once; include a metadata indexer within the existing twelve-route budget. Keep metadata requests alive through routing changes. Cache parsed reference lists so scrolling and relay updates do not repeatedly decode the same identifiers.

## Native and economical

Build with Kotlin, Jetpack Compose, Material 3, and Quartz. Use Coil for images and Android Media3 for video. Reuse platform controls and protocol implementations. Do not build a custom UI renderer or drawing framework.

Render lists lazily with stable event identifiers. Keep work off the main thread unless Android UI APIs require it. Disk and network I/O, image processing, substantial parsing, signature verification, and database queries belong on background dispatchers. Keep UI work limited to input, state presentation, layout, and rendering. Bound background concurrency as carefully as memory; optional cache work must never delay visible content. Bound event caches, subscription filters, in-memory snapshots, and relay connections. Coalesce updates without indefinitely delaying visible content under continuous relay traffic. Pause networking when the app is in the background.

Performance claims need measurements from release builds on real devices. Track cold launch to cached content, scrolling frame times, memory, APK size, and network use. Treat emulator observations as smoke tests, not proof of device performance. Prefer removing work over adding elaborate machinery to hide its cost.

## Media appears automatically

Load profile pictures and inline images automatically. Reuse a shared image loader, decode to display size, and prefetch avatars, images, and video posters for six notes ahead and two behind. Keep at most two speculative requests active with their own HTTP scheduling so they do not occupy visible-image request slots. Share memory and disk caches between both paths, preserve useful downloads across scrolling, and re-evaluate when metadata arrives. Plan URLs off the UI thread and cancel obsolete work or all prefetch work when backgrounded. Use full-width inline images at their natural aspect ratio, without cropping or side bars. Ordinary notes render up to 32 media attachments, including in detail views; keep compact embedded previews bounded separately. Reserve space from published dimensions or a bounded cache of prefetched image dimensions; when neither is known, correct the temporary placeholder ratio as soon as decoding supplies it. Show initials while an avatar is unavailable. Tap an image to open the full-screen gallery, never as a prerequisite for loading it. Reuse the gallery behavior from ants-android and boris-android: swiping, pinch/double-tap zoom, background switching, and image save/share actions. Keep profile search in its dedicated main-feed page. Gallery images fit the full viewport in either orientation, preserving their aspect ratio without reserving toolbar/footer space. Hide status/navigation bars with transient system-swipe access. Floating icon controls start hidden; single tap toggles them, swiping/zooming hides them, and three seconds of inactivity fades them away (respecting accessibility timeouts). Keep controls visible during menus or save/share work. Retain the numeric page counter only for multiple images. Profile avatars and banners share a dedicated gallery, ordered avatar then banner and opened at the tapped image; omit missing images and never expand this pair into the profile’s Photos album. Gallery overlays present 21-sat zap, reaction, and open-note actions, in that order from top to bottom, as separate 56dp circular floating buttons at the lower right. Dim and disable gallery zaps without a connected wallet; dim and disable both zap and reaction while logged out. Reuse the post action logic for the selected image’s source event, including long-press emoji and zap amount selection and reaction removal; omit counts inside these icon-only buttons. Hide these actions for images without a known source note. Pause control hiding while a picker or payment/reaction is pending, and scope engagement loading to the selected source.

Autoplay a visible video, muted by default. Keep one player and decoder active across the reading screen; initially choose the video nearest its center. Retain the current video while any part remains visible, including videos taller than the viewport. Switch only after it leaves the viewport; stop background playback. Reuse standard Android media controls and provide an accessible sound toggle.

Cache aggressively on the device. Let the reader choose a total media-storage budget in settings: 128 MB, 256 MB, 512 MB, 1 GB, or 2 GB; default to 1 GB. Reserve one quarter for images and three quarters for video, with least-recently-used eviction. Bound decoded-image memory separately. Reuse cached media across launches; Android may reclaim these cache files when storage is needed.

Avoid adding a media proxy or backend to this release. Direct loading keeps the implementation small, although first loads still download the source image. Avatars at unchanged URLs use weekly cache keys so they can eventually refresh. After loading an avatar, create a 256-pixel square WebP thumbnail on the device. Reuse that derivative for small avatars, sharing the image LRU and budget with separately cached originals. Return decoded avatars for display immediately; generate thumbnails afterward on one background worker with at most four queued writes. Deduplicate pending work and skip optional writes when full. Stop the worker before replacing its cache. Decode and encode off the UI thread; retry transient image failures twice while active. No image-processing server is needed. Video caches fill as playback buffers; the disk budget does not promise a complete offline copy of every clip.

## Identity belongs to the signer

Account access uses an Android NIP-55 signer such as Amber, exclusively. Login requests only the public identity. An explicit heart tap or picker selection requests signing of a kind-7 emoji reaction; a bolt tap requests a kind-9734 zap request and a 21-sat NWC payment; the only decryption request is for the connected account’s private mute list, through its signer. The separate wallet connection key encrypts NWC requests; identity-key encryption is not requested. Account creation and private-key management belong in the signer. A disconnected public feed is browsing, not an alternative login method.

Existing follows come from the account’s public contact list. Feather never changes those follows. Publishing is limited to explicit emoji reactions and zap requests.

## Relays are automatic

Use the account’s signed [NIP-65 relay list](https://github.com/nostr-protocol/nips/blob/master/65.md) automatically. Prioritize its read and write relays, discover followed authors’ write relays, and use a conversation author’s read relays to help find replies. Verify events before using them, respect replaceable-event ordering, and cache relay lists across launches. There is no relay configuration UI; old manual preferences are discarded.

Keep twelve built-in seed candidates for bootstrap and fallback, selecting up to four base routes at a time. Once the account’s list is available, its relays take priority in the base routes, retaining a seed for discovery. A shared pool adds up to eight routes for the account, current reading context, and authors covered by common outboxes. Route each author's notes through up to two advertised write relays, with automatic fallback when none is usable. Guests also discover relay lists for a bounded sample of visible-feed authors.

Reconcile discovery quietly while the app is in the foreground. Failed or refused connections receive a two-minute cooldown; choose another candidate without exposing a relay error or asking the reader to fix anything. Rotate seed batches every thirty seconds when no connection is available or an account's relay list is still missing. Keep healthy guest routes stable. Existing WebSocket heartbeats detect broken connections. Cancel discovery work when the app goes to the background. This is opportunistic recovery, not a guarantee that every relay is live or every note retrievable. Authenticated relays remain outside the reader's scope.

[NIP-66](https://github.com/nostr-protocol/nips/blob/master/66.md) monitor reports may eventually supplement local connection evidence. They are not implemented yet. Before adding them, define trusted independent monitors, freshness limits, and a bounded query budget. Never depend on monitoring data to connect, and never let one monitor silently remove an account's relay set. Lightweight discovery should serve reading, not turn Feather into a relay crawler.

## Review every addition

Before shipping, check the feed on a small screen and with enlarged text. Check icon semantics, touch targets, long notes, empty feeds, failed connections, and cached reading. Verify that leaving the app stops network work and that opening a profile or conversation does not lose the feed position.

A change belongs in Feather when it makes reading simpler, faster, or more beautiful without expanding the product beyond its purpose.


## Video interaction

Keep feed playback muted and limited to one decoder. Expose fullscreen and mute icons; double-tap left/right to seek ten seconds without opening the note. Vertical feed gestures continue scrolling the list. Fullscreen reuses the same player and cache, preserving the timeline, pause state, speed, and mute state across view transitions and rotation. Pause in the background and restore intentional playback on return; muted autoplay must not take audio focus from another app.

Use Media3’s native, auto-hiding timeline, play/pause, seek, playback-speed, and available subtitle controls. In fullscreen, horizontal swipes preview a seek and commit on release; left-side vertical swipes adjust this window’s brightness and right-side vertical swipes explicitly unmute playback and adjust Android’s media volume. Start from the current device volume, update only when its discrete step changes, and report the actual resulting level. Give brief icon-and-value feedback. Keep native controls accessible independently of gestures.

The fullscreen toolbar offers download, file sharing, and copy URL alongside mute and close. File exports reuse cached ranges, stream missing bytes on IO, and serialize exports without blocking playback. Store saved videos in Movies; temporary share files are retained for receiving apps, cleaned after a day on the next export, and bounded to the smaller of the selected media budget or 512 MiB. Closing fullscreen cancels an unfinished export and removes partial output. No new settings or player dependency.


## Blocktime

Default timestamps to compact relative age (`5h`, `2d`, `1w`). Tapping any timestamp cycles the app-wide format from relative age to date/time to comma-separated Bitcoin block height (`987,654`), then back to relative age. Persist this choice on IO across app restarts; new notes and all screens share it. Relative labels update at their next unit boundary only while visible and foregrounded. Resolve only requested timestamps through mempool.space’s block timestamp endpoint; retain the date while loading and when unavailable. This maps the note time to a block timestamp at or before it, not a cryptographic proof of publication time. Use one lookup at a time and a 512-entry memory cache backed by a permanent timestamp-to-height SQLite table in app data. Persist successful results on IO before displaying them, with no expiry or pruning; repeated timestamps read the stored result even after restart or memory eviction. Migrate valid legacy JSON entries, including expired ones. Failed lookups have a short retry cooldown and are not stored permanently. Cancel foreground lookups when backgrounded. No new settings or offscreen block-height prefetch.

## Loading and link previews

Reserve the feather for identity, never a loading or empty-state indicator. Show a small native spinner for pending content, including background preparation and brief cache/relay handoffs. Leave settled empty feeds quiet; retain tappable diagnostics for errors, unavailable posts, and hidden content. The system launch screen uses a transparent feather drawable on the current light/dark surface.

Animate GIFs with Coil's native image decoders. Stop animation outside the visible window, behind fullscreen media, and when backgrounded. Keep image downloads and decoding in the existing bounded cache pipeline.

YouTube links show lightweight cards: thumbnail, title, and channel attribution. Render the thumbnail immediately, then fetch oEmbed metadata in the background only for visible cards. Cache responses within the media disk budget and bound metadata memory to 128 entries. Show at most two previews per note and one per embedded note. Preserve the original link, including timestamps. YouTube preview cards and inline links prefer NewPipe, then the official YouTube app, then another Android video-link handler where supported, falling back to the browser. Use explicit package intents for NewPipe so Android web-link verification does not redirect it to the browser. No app-selection setting. No WebView or embedded YouTube player.

Other web links use the same card limits and show Open Graph images, titles, descriptions, and a visible destination domain. Fall back to Twitter metadata and HTML title/description; keep a compact domain card when metadata is unavailable. Extract links and parse HTML off-main, reuse jsoup, and do not execute scripts or embed a browser. Limit HTML reads to 256 KiB, stop after the head when possible, allow at most three HTTPS redirects, and fetch at most two pages concurrently with a 12-second overall timeout. Metadata expires after a week and shares the existing media disk budget; memory is capped at 128 entries and failed lookups have a five-minute cooldown. Pause fetches when cards leave the viewport or the app backgrounds. Reject local-network preview destinations and skip direct media links already rendered as attachments.

## Video loading and sizing

Warm video bytes before playback: look twelve notes ahead and two behind, prioritize visible waiting clips, and keep up to three distinct URLs queued. Use two IO workers with separate HTTP scheduling, read at most 4 MiB per clip into the same video LRU used by playback, and retain useful partial bytes when canceled. Stop speculative jobs when their clip becomes active, leaves the look-ahead window, or the feed backgrounds or is covered. Fullscreen playback takes priority over prefetch. Keep only one ExoPlayer and no extra video decoders.

Keep portrait media full-width at its actual aspect ratio. Use valid imeta dimensions without clamping them to landscape proportions, optionally read dimensions from an already-cached prefix on IO, and correct the layout from Media3’s actual video-size callback. Keep a bounded observable cache of 256 ratios. Unknown dimensions temporarily use a landscape placeholder; the decoder’s dimensions replace that fallback when available. Preview reads never fetch extra bytes merely to discover dimensions.

### Back navigation

Every profile, thread, and hashtag visit belongs to a navigation stack. Android Back and the toolbar arrow pop one visit; only the root feed exits the app. Keep each visit’s list position, profile tab, toolbar visibility, and saved expanded-content state. Retain displayed events for the eight most recent visits in memory so returning does not briefly collapse a long list while the repository switches subscriptions. Filtering and merging retained pages stays off-main. Save only route identifiers, relay hints, and small UI state across activity recreation, never serialized event payloads. Modal sheets, galleries, and fullscreen videos dismiss before navigating. Login/logout reset the stack for the new session.

### Profile media and bookmarks

Offer Photos (kind 20 and images in kind 1), Videos (21, 22, 34235, 34236 and videos in kind 1), and public Bookmarks (10003, 30003) only after discovering matching content. Prioritize Posts, Highlights, Photos, Videos, Articles, and Replies in that order when available; order other tabs by matching events observed in the bounded local history, breaking ties by stable tab order. This is an observed count, not a network-wide total. Use a horizontally scrollable icon tab bar.

Photos use three-column lazy thumbnail rows and the existing gallery. Videos reuse the single autoplay player, fullscreen controls, media cache, and HLS decoder. Read media URLs and MIME types from imeta even when absent from the caption; choose one video variant rather than rendering every resolution. Fetch each selected kind independently through every advertised write relay using finite requests with at most four concurrent sockets, separate from the small live subscription and home-feed connection pool. Cancel pending requests when switching profiles/tabs or backgrounding. Use the same routes for older pages; fall back to base relays only while write routes are unknown. Profile pull-to-refresh explicitly restarts the selected-kind request without resetting home-feed pagination.

Public bookmarks show lazy reference cards, resolve only the visible/nearby items with bounded subscriptions, and open addressable items through the existing external-reader fallback. Never render or decrypt private bookmark content. Keep the latest replaceable/addressable list version so removed entries do not return from old cached pages. Profile biography chevrons are centered. When a profile supplies a Lightning address, a bolt to the left of copy-npub copies that address without initiating a payment.

### Published apps

An Apps tab displays kind-32267 software metadata signed by the viewed profile. Keep the latest event per publisher and app identifier, order the tab using the same observed-frequency rule, and cache at most 300 app records. Probe the catalog relay with a small author-scoped subscription while viewing a profile, alongside normal write-relay discovery; expand the catalog query only when Apps is selected. Unsubscribe when leaving the profile. Cards show the icon, name, and summary, using existing bounded media caching and prefetch. Publisher-specific naddr links open in Zapstore when installed, with a browser fallback. Installation and updates remain in Zapstore. Indexer-signed listings are not attributed to a developer without that developer’s signature.

The website follows the system color scheme with CSS alone, using the same light and dark palette as Android, including contrasting button text and browser theme colors. No theme preference or script is introduced.

### Articles, people, and projects

Article lists use title-first borderless rows: a two-line plain-text excerpt, an optional 88dp cover thumbnail on the right, and quiet author/time metadata below, including a 24dp author avatar and a clock icon with compact estimated reading time (for example, “5m”, “1h”, or “1h 15m”) and a calendar icon with a fixed short date such as “Oct 21”, independent of the global note timestamp mode. Estimate from the full article at 200 words per minute, rounded up, excluding image markup and URLs; calculate off-main and retain at most 128 results. Parse bounded excerpts off-main; tapping the title, excerpt, or thumbnail opens the article. Full articles use native text with background Markdown formatting, cover images, and inline media. The article opens from its cached event; no browser is required to read it. People lists expose only public follows and public list members, with lazy rows and metadata discovery for visible members. Projects show the repository name and description and link to its published web address. Tabs remain icon-only and conditional on public activity, with Posts, Highlights, Photos, Videos, Articles, and Replies prioritized in that order and remaining tabs ordered by observed frequency. No follow editing, private people-list decryption, or code collaboration tools are added.

### Orange-heart reactions

Tapping a post’s heart sends a NIP-25 kind-7 event with content 🧡 through the connected signer. Guests are taken to signer login and must tap again to react. Keep signing, response verification, persistence, and publishing off-main. One reaction may be pending at a time; show a small spinner, then the most recent accepted reaction emoji (or custom emoji image) after relay acceptance. Never turn a second tap into deletion or create duplicate reactions for the same account, note, and emoji. Store the signed event before publishing so a manual retry after network failure or process restart reuses its ID. Retain at most 256 local reaction records. Use automatically discovered account write relays and the author’s read relays within the connection budget. Signer rejection and network failure return to a retryable state; no automatic publishing queue or background service.

### Account mute lists

Automatically honor the connected account’s NIP-51 muted/blocked public keys (kind 10000; deprecated kind 30000 with d=mute only if no current list exists). Hide authored notes, replies, reposts, reactions to hidden posts, bookmark targets, and embedded notes across cached navigation and media prefetch. Decrypt only the account’s own private mute list using its signer, off-main, with NIP-44 and legacy NIP-04 support. Cache the resulting public-key set privately for startup/offline filtering; retain known private mutes while a replacement awaits approval. Never publish or display decrypted entries. A cancelled/failed request leaves public and previously cached private filtering active and reports that private-list loading failed. No list editor or additional configuration.

### Reaction picker

Keep a normal heart tap as 🧡. Long-press opens a small native six-item emoji menu with an additional full-picker icon, including custom NIP-30 emoji used by the account. Put the most recent choice first, then rank frequency with a 30-day recency decay, filling remaining slots with 🧡 😂 🔥 🤙 💜 🙏. Open the AndroidX emoji picker in a native bottom sheet for the full Unicode selection, categories, and variants; add offline English name/keyword search above it, loading the bundled Unicode index on IO and filtering on a background dispatcher. Keep category browsing when the query is empty. Instantiate it only on demand and route selections through the same signing and duplicate protections. Compute suggestions off-main from a bounded own-author history query and accepted local receipts; exclude pending/rejected local sends unless independently seen on relays. Freeze choices while the menu is open. Already-sent choices are marked and disabled, but another emoji may be sent to the same note. Retry identity is per account, target, and emoji (including a custom emoji’s URL). Preserve existing orange-heart receipts during migration.

### Home feed pages

Home is a native horizontal pager with full-screen feeds and no tab bar. Prioritize Posts, Highlights, Photos, Videos, Articles, and Replies in that order when available. Posts and Replies remain available on home while other categories are discovered. Discover profile categories from followed accounts (or public relays for guests) and order the remaining categories by observed frequency. Keep discovered pages available during the visit. Defer reordering during gestures and preserve the selected category by identity when its index changes. Each page owns its list position, toolbar state, and cached content; returning from a note/profile restores the same page. The Feather button scrolls the current page to its top. Only the settled page drives live reading subscriptions, pagination, and video; a cancelled swipe keeps the previous page active. Neighbor pages use cache-only images. Bound discovery requests and compute category samples off-main, at most every five seconds or on refresh/account changes. Photos albums contain up to 600 images, with source-note navigation preserved. No feed configuration or new visible labels.

The full reaction picker automatically reads the connected account’s public kind-10030 emoji tags and up to 16 referenced kind-30030 sets. Never decrypt list content or edit collections. Show custom emoji in a horizontal row and include their shortcodes in local search. Keep at most 256 choices per source and 1,024 combined choices; previously used custom reactions come first. Parse lists and query storage off-main, load images lazily through the existing media cache, and sign only the selected kind-7 reaction.

### Wallet and zaps

A wallet icon in settings opens a minimal Nostr Wallet Connect sheet. Paste a connection, verify payment permission, and store it encrypted with Android Keystore. Save connections separately per Nostr account on this device, encrypted with Android Keystore. Logout deactivates wallet access without deleting credentials; signing into the same account restores its saved connection. The trash action deletes only the active account’s connection. Never use a different account’s wallet. Keep the sheet minimal without explanatory text. A missing wallet opens setup without paying automatically.

An explicit bolt tap signs a public NIP-57 request through the Android signer and pays exactly 21 sats through NWC. Long-press opens a compact amount picker: show only the connected account’s recent confirmed local zap amounts when available. Use 21, 42, 69, 210, 420, 2,100, 9,001, and 69,420 sats only when no history is available. Always offer an icon for custom whole-sat entry. Keep one-tap zaps at 21 sats. Apply the selected amount to both the signed request and invoice validation. No balance polling or automatic payment retries. Serialize signer actions and payments. Verify the invoice amount, checksum, expiry, request-description hash, and payment-preimage hash before reporting success. Persist the invoice before sending; after interruption, check that same invoice with the wallet instead of creating another payment. Keep the network engagement count driven by receipts. Wallet I/O and cryptography run on IO.

### Sensitive content

Hide author-marked sensitive content by default, including media grids, embeds, reposts, and bookmarks. Honor NIP-36 content warnings even without a reason, content-warning labels, and explicit NSFW tags. Settings offers an 18+ icon beside the opt-in switch, off by default, with an accessible description explaining that it enables NSFW and content-warning tagged content. Do not infer safety from missing tags or add a remote classifier.

### NIP-22 comments

Read kind-1111 comments alongside kind-1 replies. Lowercase e/a/i tags identify the immediate parent; uppercase root-scope tags must not be treated as direct replies. Resolve event and article parents through the existing bounded cache and relay pipeline; external HTTPS scopes open in the system handler. Keep comment content as plain text with the existing rich reference/media rendering. Include comments in engagement counts and bound stored comments to 2,000 events. Outgoing comments use the same NIP-22 root and parent scope through the explicit reply composer.

### Profile internet identities

Keep the display name as the profile heading. Prefer NIP-05 over the secondary username when supplied, displaying root `_@domain` claims as just the domain. A matching domain record gets a green check; matching root identities get a double check. Invalid claims get a warning. Pending lookups use a small spinner; network/server unavailability stays neutral and never implies a key mismatch. Tapping opens copyable verification details.
